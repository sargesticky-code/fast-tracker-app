## Feeds and bookmaker coverage

### Repository evidence
- `sync-fast-tracker` ingests canonical files including `hkjc_current.csv`, `forebet_current.csv`, `model_current.csv`, `form_current.csv`, aliases, fallback data and H2H summaries from the separate `football-fast-tracker` data repository.

### Conclusion
The upstream pipeline contains two genuine bookmaker identities: **HKJC** and **Bet365**. HKJC has current usable price rows in the active app path. Bet365 has a real HDA collection/matching pipeline, but the currently audited `bet365_current.csv` is header-only, so there is still **no verified live multi-bookmaker comparison**. OddsMath has timestamped HDA observations but is an aggregator/reference signal, not a second named bookmaker. “Multisource” prediction consensus is not bookmaker coverage.

### Gaps
- Provider/market inventory now exists in `docs/provider-inventory.md` and distinguishes bookmakers, aggregators, prediction providers, stats providers and internal models.
- Canonical provider/market quote contracts now exist in `lib/market-provider-contract.js` and migration `202610030530_market_provider_quote_contract.sql`; `sync-fast-tracker` contains normalized HKJC/Bet365/OddsMath quote ingestion. These changes are branch code only until the migration/function changes are actually applied to Supabase.
- Multiple distinct bookmaker integrations require real authorized feeds/credentials or another lawful source; none should be invented.
- BTTS appears in multisource/model fields, but bookmaker-priced BTTS coverage has not been verified from the current HKJC path.

## Goals-market pipeline repair

Artifact: `docs/goals-market-pipeline-audit-2026-10-03.md`.

A concrete market-specific wiring defect was found. Team Form already produced validated expected-goal estimates with source/sample metadata, and the public Phase 1 feed exposed them in `formDetail`, but `app-match-analysis` did not use them for goals recommendations. It only considered Forebet, Dixon-Coles and native multisource O/U evidence.

PR #2 now queries the canonical `form_predictions` row directly and admits Team Form to the goals family only when `quality=FORM_MODELED`, both sides have at least 8 matches, expected-goal inputs are valid and a real market line exists. Prematch method is `FORM_XG_POISSON`; it remains a distinct single evidence family.

Real FB6231 evidence verifies the affected path:

- goals 4.5 at HKJC 1.80 / 1.90;

- source `martj42/international_results + HKJC recent · recency-weighted Team-Form Poisson`;

Current coverage also distinguishes real missing inputs from wiring: 48 upcoming-selling fixtures are FORM_MODELED, 9 have no form row, and the rest explicitly fail sample/effective-weight gates. Among fresh-priced fixtures, only two currently have a usable Team Form goals model and neither has a second usable goals family.

The English article now displays the goals line/selection/price/as-of, evidence-family count, model method, Team Form sample/source/xG and an explicit statement that model expected goals are not observed xG and that HDA consensus is not reused for unrelated markets.

Production has not been deployed, so the post-fix endpoint JSON remains unobserved; its expected behavior is branch-code reconstruction until deployment.

## Source-record / player identity follow-up

Detailed artifact: `docs/source-record-player-identity-audit-2026-10-03.md`.

The audit found that provider confirmation and canonical player identity were previously conflated. Of 584 stored player-status rows, only 162 currently join to `phase2_players`; all 162 are API_FOOTBALL rows, while 408 source-confirmed FOTMOB rows do not currently resolve to the canonical player registry. Confirmed lineup evidence has the same pattern: API_FOOTBALL rows resolve, while the large FLASHSCORE_OFFICIAL set currently does not.

Review code now requires both source confirmation and canonical player identity before a player/status row can become a confirmed fact. Source-confirmed unresolved rows remain explicit. Missing player evidence remains unknown rather than zero.

Material article claims now carry durable evidence keys and stored source links when available. Human claim de-duplication is based on the underlying canonical player/status record group rather than provider name. Model evidence likewise requires known historical lineage before it can count as independent; unknown-lineage multi-source aggregates remain supplemental.

The audit also found and fixed an H/A consumption bug: Phase 2 tables store `H` / `A`, while older analysis/detail UI counted `HOME` / `AWAY`.

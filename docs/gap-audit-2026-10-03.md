This audit records repository evidence, not a completion percentage.

- Development repository: `sargesticky-code/fast-tracker-app`.
- PR #2 (`homepage-forebet-v1` -> `main`) is open, draft, unmerged and currently GitHub-mergeable.

## Feeds and bookmaker coverage

### Repository evidence
- `sync-fast-tracker` ingests canonical files including `hkjc_current.csv`, `forebet_current.csv`, `model_current.csv`, `form_current.csv`, aliases, fallback data and H2H summaries from the separate `football-fast-tracker` data repository.
- `app-match-analysis` falls back to `hkjc_odds_current` and uses HKJC HDA/goals/corners prices and lines.
- `app-phase1-feed` exposes HKJC prices, HDA models, goals/corners line models, odds movement and source context.
- No distinct Bet365, Pinnacle or other bookmaker adapter/feed was found in the current app repository during this audit.

### Conclusion
Current evidence supports **HKJC bookmaker coverage**, not verified multi-bookmaker coverage. “Multisource” model consensus is not a substitute for multiple bookmaker price feeds.

### Gaps
- Need an explicit provider/market inventory artifact generated from actual tables/ingest contracts.
- Need a normalized bookmaker-observation model before best-price comparison can be truthful.
- Multiple distinct bookmaker integrations require real authorized feeds/credentials or another lawful source; none should be invented.
- BTTS appears in multisource/model fields, but bookmaker-priced BTTS coverage has not been verified from the current HKJC path.

## Model and evidence pipeline

### Working foundations
- HDA evidence families include Forebet, internal Dixon-Coles/Pi family, Team Form and external/multisource consensus where available.
- Market-specific analysis code exists for Asian handicap, goals and corners.
- Candidate classes distinguish missing/stale data, no model, no edge, lean/watch and stronger value states.
- Odds movement reads timestamped windows from `odds_movement_current`.
- Human-factor queries include player status, lineup and manager evidence.
- Phase 3/live queries include live score, live stats, live odds, expected-vs-actual state and scenario rows.

### Gaps / risks
- The redesign branch is missing the latest main-branch fail-closed lineup-slot behaviour.
- Some user-facing strings in analysis/detail/story functions remain Chinese and require an English-first public presentation pass without changing raw/source-native data.
- Injury counts in analysis currently contain fallback logic that must be audited carefully so “missing evidence” never becomes a misleading zero-strength conclusion.
- Source freshness is present in several structures but is not yet presented consistently in public match/article UI.
- Need explicit verification fixtures for conflicting evidence families and each market-specific calculation.

## Recommendation articles / story interpreter

### Working foundations
- `app-match-story` exists with deterministic fallback and optional AI narration.
- Cache/versioning uses an evidence/data hash in `match_interpretations`.
- Story generation consumes analysis, detail, commentary evidence, phase coverage and invalidators.
- Prompt contract instructs the AI layer to use supplied verified evidence only and not invent/recalculate facts.
- The story layer retains confirmed flags and source names for lineup/player status rows.

### Gaps
- Phase 1 feed currently requests cached story summaries with `language = zh-HK`; this conflicts with the new English public product direction.
- Public homepage/detail flow does not yet surface a substantial English article with the complete required evidence structure.
- Article schema/UI still needs explicit bookmaker/market/line/price/as-of presentation, sample periods, factual-vs-model-vs-editorial separation, source references and visible stale marking.
- Need real-data verification that article claims resolve back to stored evidence rows.

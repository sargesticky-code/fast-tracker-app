## Feeds and bookmaker coverage

### Repository evidence
- `sync-fast-tracker` ingests canonical files including `hkjc_current.csv`, `forebet_current.csv`, `model_current.csv`, `form_current.csv`, aliases, fallback data and H2H summaries from the separate `football-fast-tracker` data repository.
- `app-match-analysis` falls back to `hkjc_odds_current` and uses HKJC HDA/goals/corners prices and lines.
- `app-phase1-feed` exposes HKJC prices, HDA models, goals/corners line models, odds movement and source context.
- No distinct Bet365, Pinnacle or other bookmaker adapter/feed was found in the current app repository during this audit.

### Conclusion
The upstream pipeline contains two genuine bookmaker identities: **HKJC** and **Bet365**. HKJC has current usable price rows in the active app path. Bet365 has a real HDA collection/matching pipeline, but the currently audited `bet365_current.csv` is header-only, so there is still **no verified live multi-bookmaker comparison**. OddsMath has timestamped HDA observations but is an aggregator/reference signal, not a second named bookmaker. “Multisource” prediction consensus is not bookmaker coverage.

### Gaps
- Provider/market inventory now exists in `docs/provider-inventory.md` and distinguishes bookmakers, aggregators, prediction providers, stats providers and internal models.
- Canonical provider/market quote contracts now exist in `lib/market-provider-contract.js` and migration `202610030530_market_provider_quote_contract.sql`; `sync-fast-tracker` contains normalized HKJC/Bet365/OddsMath quote ingestion. These changes are branch code only until the migration/function changes are actually applied to Supabase.
- Multiple distinct bookmaker integrations require real authorized feeds/credentials or another lawful source; none should be invented.
- BTTS appears in multisource/model fields, but bookmaker-priced BTTS coverage has not been verified from the current HKJC path.

## RLS security advisory

The connected Supabase schema audit reports Row Level Security disabled on three existing internal tables:

- `public.phase1_identity_deferred_queue`
- `public.phase1_h2h_provider_event_map`
- `public.phase1_h2h_provider_meetings`

This phase did **not** auto-enable RLS because doing so without reviewed policies can break legitimate access. The new market-provider migration was separately hardened to enable RLS and revoke anon/authenticated access on its new tables/view before any production application.
